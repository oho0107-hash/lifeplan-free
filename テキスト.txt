LIFEPLAN — AIエージェント作業指示書
ゴールと制約
	●	GAS不使用。iPhone の Safari で利用できる静的 Web アプリを維持する。
	●	利用者が新たな有料 API・クラウドサービスに登録しなくても使えること。
	●	実際の氏名、生年月日、給与、住宅ローン残高、API キー、保存データは GitHub リポジトリに書き込まない。
	●	現行アプリは既存 GAS v25 の 概算モデルからの移植であり、法令・公的制度の正確性は未認定。
	●	相談者への確認が必要な計算前提を、エージェントが勝手に確定させない。
作業の流れ
	1.	要件検討エージェント：利用者の要求を REQ-ID 付き要件（入力項目、単位、計算式、適用年度、境界値、受け入れテスト）に変換する。
	2.	専門家観点レビュー（6役）：以下の観点をそれぞれ独立に検討する。これらは AI のレビュー役割であり、有資格者による監修を意味しない。
	3.	レビュー統合エージェント：矛盾を統合し、問題ごとに重大度、根拠資料、解決策、テストを示す。「重大・高」が残る場合は、無条件で金融判断用として公開しない。
	4.	実装エージェント：承認された要件だけコード修正。コードと独立期待値のテストをセットで更新する。
	5.	実操作QAエージェント：iPhone 幅の仮データをフォームに入力、結果画面や保存を確認。計算ロジックとは別に求めた期待値と比較する。
	6.	リリース承認：GitHub Actions のテストが緑であり、重大な問題が解決・明示され、利用者が承認したときに限り本番版とする。
6つのレビュー役割
A. ファイナンシャルプランナー視点
資産推移、収支とストックの整合、複数人の教育費ピーク、利回りと物価上昇、赤字・借入の扱い、年初/年末資産の違い。
B. 社会保険・税務視点
育休中の給付・給与、税・社会保険、児童手当、扶養人数、将来の年金。公的根拠 URL・適用日・対象条件を明記し、未調査なら未検証と書く。
C. 教育資金・教育制度視点
4月基準の学年、保育費、受験準備、学校段階別費用、公私立、無償化、大学の扶養要件、奨学金の扱い、実家/一人暮らし。
D. 住宅ローン・金融視点
元利均等、ボーナス払い、金利変更、5年・125% ルールの契約適用、繰上返済、銀行の返済予定表との差、残債。
E. セキュリティ・プライバシー視点
ソースコードに実家計データを含めないこと。ブラウザ保存、バックアップの復元、公開 URL、データ消去・端末移行リスク。
F. 品質保証・システム視点
入力エラー、桁あふれ、日付境界、0% 金利、収入ゼロ、4人目切り替え、赤字継続、ブラウザのリロード、モバイルUI。
指摘の出力形式
|ID|役割|重要度|根拠/コード箇所|現象と再現条件|正しい期待値|修正提案|確認状況| |--|--|---|--------|-------|------|----|----|
根拠がない制度解釈は「要調査」とし、推測値を確定値として記載しない。
優先対応事項（初期レビュー）
	●	R-01: 児童手当・多子世帯の大学無償化の適用期間や扶養要件を年度別に再検証。
	●	R-02: 育休給付と年金を単純な固定値から分けてモデル化。
	●	R-03: 住宅ローンのボーナス返済・金利改定・繰上返済を正確な月次計算と比較。
	●	R-04: 「純資産」の表示名が住宅ローン残債を含まないことを明記。
	●	R-05: 教育区分を誕生日の暦年ではなく学年・4月進級基準で検算。
	●	R-06: 本人の了承なく本番個人データやバグ再現に利用した個人データをコミットしない。
テスト・無料運用
	●	GitHub Actions (.github/workflows/iphone-verify.yml) の緑は「その設定のテストに合格」した意味だけ。制度面の監修完了ではない。
	●	追加の API 課金なしでは、AI 役割の呼び出しとレビュー統合は ChatGPT 内で明示的に実施する。GitHub Actions は固定の自動テストを実行する。
	●	AI同士の完全自律的な再帰レビュー、勝手なコード書き換え、24時間稼働は 現段階では未実装。存在するかのように説明しない。
