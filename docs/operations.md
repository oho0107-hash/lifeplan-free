# 運用・復旧と外部設定

日々のiPhone操作は[IPHONE_OPERATIONS.md](IPHONE_OPERATIONS.md)、開発の工程と停止条件は[DEVELOPMENT.md](DEVELOPMENT.md)を参照する。

既存のIssue受付を統合して使用する。同じIssueの提案PRがあれば（closedを含め）再生成せず再利用し、新しい要望は新しいIssueとして扱う。途中でbranch push後にPR作成が失敗した場合は、同じIssue番号でActionsを再実行すると草案PRの作成だけを回復する。回復jobはブランチをcheckout・実行・更新せず、mainに属する親commit、単一のbot提案commit、許可された差分、元の所有者起動runと成功した独立検証、レビュー・実行証拠と候補のハッシュ一致、元runに保持された提案・検証artifactとの一致を確認する。ブランチが人に更新された場合や証拠・元runを確認できない場合や元artifactの保持期限が切れた場合は上書きせず停止する。その場合も手動コード操作は不要で、Codexへ「Issue番号と既存ブランチの草案PR作成を回復して」と依頼し、元の証拠と差分を調査させる。回復時のテスト再実行や公開を実施したとは扱わない。すべての自動生成PRは草案として証拠と未検証を記録し、重要な計算/制度/金額/セキュリティ/権限変更は承認を経る。

GitHubのbranch protection/rulesetやPages environmentはファイルを追加しただけでは有効にならない。リモート管理権限で実設定を確認できない場合は未確認として扱い、自動マージしない。最低限、mainへの直接push/保護迂回を防ぎ、`lifeplan/independent-quality`相当の独立品質検査と制度/金融監査の成功、最新baseへの追従、レビューを必須にする。Pages environmentの重要変更承認を設定する。実際の必須チェック名は初回Actions実行に表示されたものに合わせて設定し、名前だけで成功を偽装しない。

Pages公開は共通回帰テストと独立金融strict診断の成功を前提にする。現在のHigh3件は診断が失敗して公開を止める。元の計算問題を修正し、制度前提を検証して承認されるまで解除しない。公開後HTTP smokeと実ブラウザの重要操作を区別する。

障害時は新規公開を止め、前の検証済みSHAへのrevert PRを作成し、同じ全ゲートを再実行する。未検証の自動ロールバックやforce pushで復旧したと扱わない。権限がなければ復旧差分/手順を保存して未実行と報告する。
